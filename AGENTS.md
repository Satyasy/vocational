# AI AGENTS GUIDE & WORKSPACE CONTEXT (AGENTS.md)

Dokumen ini adalah **pedoman wajib** (*ground truth context*) bagi seluruh agen AI (GitHub Copilot, Cursor, Gemini CLI, Claude, ChatGPT, dsb.) saat membuat, memodifikasi, atau mereview kode pada repositori ini.

Agen AI **DILARANG KERAS** membuat asumsi arsitektur sendiri atau mengubah pola yang sudah ditetapkan tanpa instruksi eksplisit dari pengguna.

---

## 1. Arsitektur Repositori

Repositori ini menggunakan arsitektur **Monorepo** dengan manajer paket **pnpm Workspaces**.

```text
vocational/
├── apps/
│   ├── web/               # Frontend: Astro v7 (SSG/SSR, Content Collections, Tailwind)
│   └── api/               # Backend: NestJS v12 (Modular architecture, Vector search, REST API)
├── packages/
│   └── shared/            # Single Source of Truth (@repo/shared): Types, DTOs, & Contracts
├── package.json           # Root package.json (devEngines: pnpm@12.15.0)
├── pnpm-workspace.yaml    # Workspace definition
└── AGENTS.md              # File ini (Agent System Instructions)
```

---

## 2. Aturan Mutlak Monorepo & Package Management

1. **Wajib `pnpm`**: Dilarang menyarankan atau menjalankan perintah `npm`, `yarn`, atau `bun`. Seluruh dependensi dikunci pada `pnpm`.
2. **Jangan Install di Subfolder**: Dilarang mengeksekusi `cd apps/web && pnpm install`. Instalasi dependensi hanya dilakukan dari root.
3. **Pemasangan Dependensi Baru**: Wajib menggunakan flag `--filter`:
   - Frontend: `pnpm --filter web add <package>`
   - Backend: `pnpm --filter api add <package>`
   - Shared: `pnpm --filter @repo/shared add <package>`
   - Root dev tool: `pnpm add -D -w <package>`
4. **Koneksi Internal Workspace**: Selalu gunakan `workspace:*` untuk paket internal (contoh: `"@repo/shared": "workspace:*"`).

---

## 3. Kontrak & Data Sharing (`@repo/shared`)

`packages/shared` adalah **Single Source of Truth** untuk tipe data antara Backend dan Frontend.

### Aturan Kerja Agen:
1. **Dilarang Duplikasi Tipe Data**:
   - Dilarang membuat definisi interface yang sama di dalam `apps/web` dan `apps/api`.
   - Jika fitur baru membutuhkan entitas, request, atau response baru, **definisikan terlebih dahulu di `packages/shared/index.ts`**.
2. **Impor Kontrak**:
   - Frontend dan Backend wajib mengimpor dari `@repo/shared`:
     ```typescript
     import type { VectorSearchRequest, SearchResultItem } from '@repo/shared';
     ```
3. **DTO di Backend**:
   - Class DTO di NestJS harus mengimplementasikan interface dari `@repo/shared` untuk memastikan keselarasan tipe data:
     ```typescript
     export class SearchDto implements VectorSearchRequest {
       query: string;
       topK: number;
     }
     ```

## 4. Komunikasi Jaringan & Arsitektur API (Runtime Boundary)

Agen AI harus memahami batasan runtime antara Frontend dan Backend:

1. **Bukan Direct Import Saat Runtime**:
   - `@repo/shared` hanya berbagi tipe/kode pada waktu kompilasi (*compile-time*).
   - Data backend **TIDAK** otomatis tersedia di frontend tanpa HTTP/REST call.
2. **HTTP Request / REST API**:
   - Frontend (`apps/web`) berkomunikasi dengan Backend (`apps/api`) melalui HTTP request (misal: `fetch`).
   - Jangan pernah melakukan *hardcoded* URL `http://localhost:3000` di dalam kode frontend. Gunakan environment variable:
     ```typescript
     const apiUrl = import.meta.env.PUBLIC_API_URL || 'http://localhost:3000';
     ```
3. **CORS & Environment Variables**:
   - Backend NestJS wajib mengizinkan CORS dari frontend origin (`process.env.FRONTEND_URL || 'http://localhost:4321'`).
   - Gunakan format konfigurasi standar yang terdokumentasi di `.env.example` masing-masing service.

## 5. Standar Kode & Tooling

1. **TypeScript Strictness**:
   - Selalu sertakan tipe data yang jelas (hindari penggunaan `any` tanpa alasan kuat).
   - Gunakan `import type { ... }` ketika mengimpor interface/type saja.
2. **Linting & Formatting**:
   - Backend menggunakan `oxlint` untuk fast linting dan `prettier` untuk formatting.
   - Jangan menambahkan linter berat lain (seperti ESLint standar) kecuali diminta.
3. **Menjalankan Script**:
   - Jalankan dari root:
     - `pnpm dev` : Menjalankan backend dan frontend serentak.
     - `pnpm dev:api` : Menjalankan NestJS saja.
     - `pnpm dev:web` : Menjalankan Astro saja.
     - `pnpm build` : Memvalidasi kompilasi seluruh workspace.
     - `pnpm lint` : Menjalankan linter.

## 6. Aturan Git & Commit Message

1. **Identitas Commit Developer Asli**:
   - Setiap commit wajib menggunakan identitas git user (`user.name` & `user.email`) yang terkonfigurasi pada terminal developer/lingkungan lokal.
   - **DILARANG KERAS** menyisipkan atribut AI, co-author AI, atau embel-embel generator (seperti `Co-authored-by: Claude`, `Generated by Copilot`, `Assisted by Antigravity`, `Gemini`, atau bot signatures lainnya) di dalam commit message maupun commit description.
2. **Pesan Commit Bersih**:
   - Gunakan pesan commit yang deskriptif, bersih, dan profesional (misal: Conventional Commits seperti `feat: ...`, `fix: ...`, `chore: ...`).
